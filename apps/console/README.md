# DroneOps operations console placeholder

Phase 0 intentionally does not install a JavaScript framework or create any scheduling logic in the browser.

The future console will use React, TypeScript, Vite, MapLibre and deck.gl. Planned primary views:

- map and 4D reservations;
- fleet, pads and chargers;
- mission queue;
- decision trace;
- scenario replay;
- exception and uncertainty state.

Every view must distinguish planned, committed, observed and synthetic data.

## Generated API types (Phase 4 control plane)

The console is typed from `contracts/openapi/v1.yaml` - one source, no hand-written
duplicates. The generator is **not** in `package.json` devDependencies yet, so these types
have **not** been generated by the API work; the command below is the step to run (and the
step to wire into the Makefile as `console-types`, next to `console-install`):

```bash
# from the repository root, with the console's lockfile honoured (no ad-hoc installs)
make console-install
npx --yes openapi-typescript@7 contracts/openapi/v1.yaml   --output apps/console/src/generated/api-types.ts
```

Expected output once run: `apps/console/src/generated/api-types.ts` containing
`components["schemas"]` entries for `OrderRequest`, `OrderResponse`, `MissionResponse`,
`PlanVersionResponse`, `ReservationResponse`, `DecisionTraceResponse`, `RejectedCandidate`,
`EligibleAircraft`, `CandidateRanking`, `DecisionInputs`, `TelemetryObservationResponse`,
`UncertaintyStateResponse`, `AircraftResponse`, `FacilityResponse`,
`FacilityCapacityResponse`, `AuditEventResponse`, `SimulationRunResponse`,
`ReplayDiffResponse`, `ScenarioComparisonResponse`, `StatusStreamEvent`, `ErrorResponse`
and `ConflictResponse` - each carrying `phase`, `source_kind`, `authoritative` and
`simulation_notice`.

Adding `openapi-typescript` to `apps/console/package.json` is a console-side change; the
API deliverable deliberately did not touch it.
